# Qwen30 streamed-source oracle disposition

The former Python preparation chain for the Qwen30 streamed-source/raw-final-
logit oracle was removed from active HEAD in the Event Horizon compression
wave. It was an unrun future measurement plan, not a production authority,
and had no live caller outside its own controller/test chain.

## Signal retained

- The completed all-layer trace retained hashes/top-k witnesses, not raw F32
  logits; therefore it did not establish a numerical source-distance result.
- The source-BF16 co-resident preflight was fail-closed: the measured host
  could not hold the sealed source-weight lower bound plus the declared 8 GiB
  runtime reserve. No source model was loaded and no lease was granted.
- A future streamed measurement, if revived, must use bounded row windows,
  zero swap/swapouts, a separately sealed source lease, explicit non-residency
  proof, source eviction before native capture, and a receipt written only
  after payload fsyncs.
- The planned discriminator required six full F32 endpoint vectors: source,
  scalar control, and candidate at exact-prefix and forced-continuation
  endpoints. It could report only a numerical diagnostic, never coherence,
  HCLI, TPS, capability, or tournament evidence.

The current Rust diagnostic/stream-child examples remain under the frozen
product boundary. Recreating this measurement requires a new current owner
and fresh sealed contracts; the deleted Python scaffolding is recoverable from
Git history.
