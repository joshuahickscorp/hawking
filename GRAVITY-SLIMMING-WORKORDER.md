# Gravity slimming work order

This is the tracking surface for reducing Hawking's conceptual, source,
representation, and tool overhead without reducing capability. It is an
implementation work order under Gravity, not a new subsystem.

## North star

```text
smaller outside surface + fewer duplicate owners + cheaper execution
subject to capability parity, authority parity, receipt parity, and rollback
```

## Priority order and ETA bands

The end state is staged so KIMI can become a useful Gravity/ Odyssey worker
without being treated as qualified before it is measured:

| Phase | Priority | ETA band from current state | Exit condition |
|---|---:|---:|---|
| KIMI evidence closure | 1 | 2–6 clean-process runtime runs; usually hours of machine time | Candidate or explicit no-promotion result with held-out causal, capability, epistemic, authorization/HCLI, physical, destructive-control, and Nova-lineage receipts |
| Gravity ownership/consolidation | 2 | 3–8 small parity migrations; each is a separate measured pass | One canonical owner per retained capability, migrated callers, unchanged mutation/authority classes, benchmark non-regression, and rollback path |
| Odyssey reintegration | 3 | starts after Phase 1; 2–4 campaign passes | KIMI's measured capabilities are exposed as typed Odyssey WorkUnits with receipts, not as an unbounded autonomous tool |
| ModelLake continuation | 4 | ongoing after Phase 1; recurring census/lineage runs | ModelLake identity, checkpoint lineage, physical measurements, and new Star/NX candidates stay receipt-bound and resumable |

These are engineering bands, not a promise that an unqualified KIMI candidate
will pass. A failed candidate shortens the KIMI lane by closing it with a
measured rejection; it does not authorize skipping the gates. KIMI may assist
Odyssey and ModelLake only through the same HCLI authority, WorkUnit, and
receipt boundaries.

The canonical conceptual surface is:

```text
Hawking → HCLI → Gravity
                 ├─ Deep Gravity: whole model/representation/machine search
                 └─ Nova: learned-organism transformation when required
```

Odyssey is a campaign, Noetic is Gravity's mutable representation, and NX is a
Gravity-produced executable artifact. Internal tags and historical folders are
not peer systems.

## The remaining slimming fronts

The work is not complete when the folder count or tool count falls. Gravity must
also reduce:

1. **Ownership duplication** — one implementation owner per anatomy,
   representation, accounting, loader, routing, verification, and physical
   benchmark capability.
2. **Representation overhead** — count codebooks, indices, seeds, generators,
   routing data, residuals, metadata, and interpreter/kernel bytes in the same
   complete description budget.
3. **Tool-selection cost** — reduce names, schemas, catalog tokens, invalid
   retries, and recovery rounds while preserving mutation classes and required
   arguments.
4. **Build and import cost** — measure compile time, import fan-out, cold-start
   time, dependency size, and resident memory after each consolidation.
5. **Runtime cost** — measure bandwidth, cache behavior, dispatch, kernel
   selection, CPU/GPU/Metal placement, state/KV cost, and TPS together with
   useful capability.
6. **Lineage cost** — make every Nova transformation explicit, reversible where
   possible, and independently attributable to a parent and objective.
7. **Verification cost** — keep capability, epistemic calibration,
   authorization, HCLI reachability, physical performance, privacy, and
   destructive controls as separate axes rather than one optimistic score.
8. **Receipt/search cost** — preserve sealed historical evidence while making
   the active receipt/index path smaller, typed, and faster to query.
9. **Recovery cost** — retain compatibility aliases and rollback recipes until
   migration has proven that a smaller surface can recover from invalid input,
   missing dependencies, and interrupted runs.
10. **Human vocabulary cost** — expose Hawking/HCLI/Gravity, with Deep Gravity
    and Nova only when the distinction matters; keep implementation anatomy
    out of the conceptual surface.

## Safe reduction rule

For each candidate consolidation:

```text
inventory → assign one owner → preserve compatibility → migrate callers
→ run parity tests → benchmark build/runtime/recovery → seal receipt
→ deprecate → delete only after rollback window closes
```

No step may delete a historical receipt, mutate KIMI_BASE, widen HCLI
authorization, or create a promoted artifact merely because it makes the tree
look smaller. A reduction that saves bytes but loses capability, provenance,
authority, or recovery is not a Gravity win.

### Direct execution reference and fanout — 2026-09-10

The first physical reference now exists in
`tools/future/kimi_noetic_pq_reference.py`. It loads only the immutable layer-10
routed expert 23 `up_proj` tensor, fits a bounded row-wise PQ on CPU, executes
the matvec by codebook groups, and compares it with a dense matvec oracle. The
direct path was verified without dense-parent rematerialization. The initial
256-entry d32 configuration measured 3.3523 complete EBPW, 0.7628 relative-L2
error, 0.555 ms direct matvec versus 0.345 ms dense-oracle matvec, and is
rejected as a useful representation configuration.

The follow-on
`tools/future/kimi_noetic_pq_fanout.py` fans out six lower-entry configurations
against the same tensor, with six workers and a 20,000 ms per-method soft
budget. All six completed in a 2,687 ms wall fanout. The 0.5000 EBPW row was
mechanically executable but had 0.9689 relative-L2 error; the lowest-error
fanout row measured 1.0568 EBPW and 0.8224 relative-L2. This is the intended
Gravity standard: bill complete bytes, time fit/execute separately, compare to
an oracle, and let error/physical results reject attractive accounting rows.
The receipt is
`receipts/future/KIMI_NOETIC_PQ_FANOUT_EXPERT23_UP_20260910.json`.

The fanout does not falsify sub-1 EBPW for MoE. It falsifies these cheap
single-tensor, low-entry PQ settings as useful by themselves. The next
materially different discriminator is shared-codebook fitting across the MoE
organ, followed by output-aware protected residuals and organ capability
checks. No full-body, TPS, NX, or Odyssey claim is earned by this reference.
