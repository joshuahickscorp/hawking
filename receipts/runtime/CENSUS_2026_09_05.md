# Measured blockers on usable context — 2026-09-05, worktree 403b13bf1

Every number here was measured or read from source in this worktree. Labels are honest:
MEASURED = a number was produced by running something. READ = read from code/config.

## The attention ceiling is the real wall

READ     The production attention kernel materialises the full score vector in THREADGROUP
         memory — a 4-phase pass over scores[seq_len]. Not flash, not online softmax.
MEASURED The 32,768-byte threadgroup limit on this M3 Ultra caps context at 7,680 tokens
         (8,160 absolute best case). config advertises max_position_embeddings 262,144.
         A 32x gap. NOTHING IN THE CODE GUARDS IT.
READ     A flash-attention kernel with constant, context-independent threadgroup memory
         EXISTS in this repo and is wired into three other models. It is ABSENT from the
         Qwen3.8 path: zero call sites, and its env gate is never read there.

## KV

READ     KV is 131,072 B/token (128 KiB) — exactly 2x the long-standing 65,536 claim.
         Cause is DTYPE: allocated f32 while config says bfloat16. Allocated for the 16
         attention layers only; the 48/16 layer split was correct, only the rate was wrong.
MEASURED (32768-8192) x 131,072 = 3.000 GiB, reproducing an observed 11.2 -> 14.2 GiB RSS
         jump to the byte.
READ     KV is PREALLOCATED IN FULL at max_seq_len at session construction. No growth path
         anywhere. A 262,144 window costs 32.0 GiB of KV even on a 4-token task.
READ     Recurrent + conv state is FIXED at 156,893,184 B (144 MiB + 5.625 MiB) and does not
         scale. Compressing it is wasted work. KV is the only term that scales, and dtype
         alone (f32 -> bf16) is a 2x with no algorithm.

## The packet floor

MEASURED Demand floor before any mission text: 6,501 tokens with the compact catalog,
         7,334 with the full catalog.
MEASURED 4,608 of the 8,192-token window (56%) is consumed by reserves before any prompt
         byte. 2,048 of that is generation reserve the engine CAN NEVER SPEND, because
         _MAX_TOKENS_CEILING = 2048.
MEASURED The same resident yields usable_input 5632 or 3584 — a 36% disagreement decided
         only by whether the operator passed the profile .json or the artifact directory.
MEASURED An override exceeding the runtime ceiling is NOT clamped: resolve() will report
         model_ceiling=8192 and usable_input_tokens=126464 at the same time.
MEASURED context_budget.fit_or_refuse is exported and tested and has ZERO production callers.
MEASURED The worker packet is never token-preflighted in production: mission.py:1061 omits
         budget=, so goal.py:1639's preflight block is dead. Its only caller is an
         acceptance gate.
