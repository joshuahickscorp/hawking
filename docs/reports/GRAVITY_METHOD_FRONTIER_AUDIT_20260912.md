## A. Executive verdict

Gravity has a substantial method history and a useful executable control library, but a sparse library of **successful, source-bound representations at the required Flash rates**. The current registry contains **18 registry entries: 17 executable scoped procedures and one partial native-context bank method**, with 8 declared automatic adapters. The broader audit indexes 128 method/prior/negative/compiler entries, including all 39 Doctor techniques and all 14 Foundry atlas entries. These counts overlap scientific families; they are not independent successful compression methods.

The engineering target is still open. The source has 179,999,981,564 accounting logical-weight equivalents and 359,999,963,128 indexed bytes. Routed experts are 68.507% and the PLE table28.445%. The remaining tail at source precision consumes **0.487751 whole-body EBPW**. Leaving it unchanged makes the 0.5 target require an approximately0.01263 average rate across both dominant organs. Even an idealized **4-bit tail alone exceeds the entire0.1 budget**. PLE-only progress cannot solve the problem.

The strongest next science is one actual-source vector-code expert falsifier, lawful paired expert alignment, tail/router sensitivity at the needed budget, and a cheap HC closure test. PLE function work depends on the right teacher: the newly implemented native pre-layer exporter does **not** yet provide upstream PLE-inclusive source trajectories. Do not turn its real native states into the wrong source teacher.

Three radical assumptions worth testing are that independent expert bodies can collapse into shared nonlinear functions, that independent PLE histories can collapse into compact future-equivalent programs, and that future-observable state/closed-region behavior needs a much smaller description than source coordinates. These are questions, not positive findings. Thirteen specific proposals below include exactly one intentionally extreme0.01-horizon hypothesis.

**Coverage verdict:**0.5 is scientifically approachable through existing machinery plus still-unearned structural/functional representations, but no current complete survivor is established.0.1 needs joint new representation evidence for experts, PLE and tail; no known method presently earns that whole-body regime. The report narrows what to measure; it does not assume feasibility or impossibility.

### N01 — Pre-hash token-interaction PLE contribution program

**F — NEW HYPOTHESIS; WITHHOLD; SPECULATION.**

**Target:** PLE lookup + projection/gate contribution

**Mathematical/algorithmic representation:** u(history)=Σ_j A_j e(token[t-j]) + Σ_(j,k in E) B_jk(e(token[t-j])⊙e(token[t-k])); (y,s_next)=F(u(history),h,s). A bounded interaction graph replaces unrelated hashed-row coordinates; token IDs and EOS/hash semantics remain exact at the teacher.

**Key assumption:** Useful PLE outputs depend mostly on reusable token interactions before hashing; most hashed-row-specific facts can be omitted without losing held-out continuation behavior.

**Evidence and inference:** MEASURED: correct BOS PLE formula and Fourier-address failure S05. No measured Flash evidence that token interactions predict PLE outputs. The change from hash coordinate to token identity is an INFERENCE worth testing.

**Nearest existing method:** Existing frequency-tiered generator/hot islands, address Fourier screen, conditional-function prior.

**Material difference:** Tests compositional structure before the source hash; the factorization is a sparse token-interaction graph with explicitly bounded token dictionaries, not a smooth function of numeric row address or a generic row MLP.

**Complete storage/accounting:** All token feature tables, interaction graph, A/B/F parameters, EOS/history code, compact state initializers, exact exception keys+values and interpreter. No hidden 320M-row ID code array. Persistent bytes=token features+graph+program+exceptions+support.

**Direct execution:** Compute token features and interactions, then emit the contribution and next convolution state directly on GPU. Do not reconstruct the BF16 lookup table.

**Required oracle/control:** MISSING: fresh integrity-valid native-context formula bank with disjoint histories/contexts and carried PLE state.
